# Naming Generation 2 — 2026-09-16

## Status

`PROVISIONAL_FRONT_RUNNER_IDENTIFIED`

SignalForge remains the canonical runtime identifier. No repository, Worker, API, X-Agent slug, package, route, receipt, or submission-link rename is authorized by this document.

## Why this generation changed direction

The first naming pass proved that obvious governance language is unusually crowded in 2026. `proof`, `evidence`, `threshold`, `clearance`, `warrant`, and `right-to-act` compounds repeatedly collide with active AI-agent governance, authorization, provenance, or verification products.

Generation 2 therefore optimizes for a different product truth:

> The product determines whether the available evidence is sufficient to justify a conclusion.

That means the name should feel closer to **sufficiency / admissibility / grounded conclusion** than to **firewall / execution control**.

## Candidate family generated

### SUFFIRA — PROVISIONAL FRONT-RUNNER

Origin / meaning:

- derived from the French future form of `suffire`: `suffira` = “will be enough / will suffice”
- maps directly to the product’s central question: is the current evidence enough to conclude?
- naturally supports the existing product states `insufficient_evidence`, sufficiency/coverage/confidence gates, refusal, recovery, and re-evaluation

Why it is strong:

- semantically closer to the actual product than SignalForge
- does not imply execution authority or truth certification
- short, pronounceable, visually distinct, and compatible with the Prismatic Evidence Foundry identity
- current GitHub screening returned no exact product repository named `suffira`
- current web screening surfaced ordinary French-language references to the verb, not an identifiable adjacent AI/software product

Risks still open:

- French-language lexical meaning is an advantage semantically but may require a one-line pronunciation/explanation for a global audience
- `.com` / trademark availability has not yet been legally cleared
- must be tested in spoken-demo memory with non-French speakers

Current status: `PROVISIONAL_FRONT_RUNNER`

### ADMISTRA — BACKUP / HOLD

Intent:

- coined from admission / admissibility
- maps to the evidence admission ledger and the distinction between admitted vs excluded raw sources

Why it survives initial product screening:

- no exact meaningful GitHub product collision surfaced in current screening
- semantically relevant to the admission-ledger mechanism

Why it does not equal SUFFIRA:

- visually and phonetically drifts toward `administra` / administration
- `admistra.com` has registration/auction history, so clean domain acquisition cannot be assumed
- it describes one stage of the lifecycle rather than the product’s core sufficiency thesis

Current status: `BACKUP_ONLY`

### EPISTATE — REJECT

Why it was interesting:

- historically an `epistate` was a supervising/presiding magistrate, which creates an authority/oversight association
- the lexical root also loosely evokes epistemic state

Why it fails:

- existing `Epistates` GitHub organization and MCP-related repositories create avoidable collision/noise
- the historical/political term is obscure and pronunciation is not obvious enough for a hackathon/demo brand
- authority connotation is stronger than evidence-sufficiency connotation

Status: `REJECT`
